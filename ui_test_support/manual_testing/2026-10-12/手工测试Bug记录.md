# 教师工作量系统：Edge 手工测试记录

测试日期：2026-10-12（Asia/Shanghai）  
环境：UAT，<https://hssload-uat.cuhk.edu.cn>  
方式：在当前 Edge 已登录标签页中，通过页面点击、输入、切换、滚动和查看结果进行探索测试。本轮没有运行 pytest、Selenium 或已有测试脚本。

## BUG-01：审批跟踪提交时间未格式化

- 页面：`/hss-budget/approval-tracking`。
- 前置条件：当前管理员登录，2024-2025 学年、Term 1、待审批。
- 复现步骤：打开“教学计划管理 → 审批跟踪”，查看 Division of Applied Psychology 的记录及“提交时间”列。
- 实际结果：提交时间显示 `1791439302000`，是一串 13 位数字。
- 预期结果：显示可读日期和时间，并按系统统一时区格式化；用户不应自行转换毫秒时间戳。
- 影响：无法直接判断提交日期、等待时长，妨碍审批跟踪。
- 证据：[审批跟踪截图](screenshots/approval-timestamp.jpg)。

## BUG-02：分钟取整规则文案与条件矛盾

- 页面：`/hss-config/rule`，版本 2024-2025。
- 复现步骤：打开“系数规则库 → 课时计算 → 分钟取整规则”，查看名称、说明和匹配条件。
- 实际结果：

| 代码        | 名称/说明                            | 匹配条件                            |
| --------- | -------------------------------- | ------------------------------- |
| CEIL_HALF | 名称“≥30分钟取半”；说明“分钟数≥30时取半小时(0.5)” | `minutes >= 20 && minutes < 50` |
| CEIL_INT  | 名称“≥10分钟靠整”；说明“分钟数≥50时向上取整到整小时”  | `minutes >= 50`                 |

- 页面原则又写“≥50 分钟进一、≥20 分钟取半、<10 分钟舍去”。
- 预期结果：名称、说明、原则和执行条件表达同一套边界；最终阈值由业务确认。
- 影响：管理员可能根据错误文案理解或维护规则。20 分钟实际会命中名称为“≥30分钟取半”的规则。
- 证据：[规则截图](screenshots/minute-rule-inconsistent.jpg)、[页面规则原文](minute-rule-definition.txt)、[20 分钟匹配截图](screenshots/minute-20-matched.jpg)、[20 分钟测试原文](minute-20-observation.txt)。
- 本轮只查看规则，没有修改阈值、名称或规则值。

## BUG-03：分钟区间覆盖缺口与试算结果不一致

- 页面：`/hss-config/rule`，版本 2024-2025。
- 复现步骤：
  1. 在上述“分钟取整规则”中打开“条件测试”。
  2. 保留其他默认变量，将“超出整点的分钟数”分别设为 10、19、20，逐次点击“执行测试”。
  3. 取消条件测试，打开“测试计算引擎”。输入 Course Code=`PSY101`、Days\&Time=`Mon:10:00-11:10`、Term Code=`2410`、选课人数=30、Units=3，其他保留默认，点击“试算”。
- 实际结果：

| 场景               | 页面结果                       |
| ---------------- | -------------------------- |
| 条件测试：minutes=10  | 未匹配到任何规则，三条生效规则均不匹配        |
| 条件测试：minutes=19  | 未匹配到任何规则，三条生效规则均不匹配        |
| 条件测试：minutes=20  | 命中 CEIL_HALF，系数 0.5，测试通过   |
| 引擎试算：10:00–11:10 | 原始课时 1.5，最终工作量 1.5，PASS，成功 |

- 三条可见条件为 `[20,50)`、`[50,+∞)`、`(-∞,10)`，10–19 分钟没有覆盖。引擎却在该区间成功返回 1.5，并未说明采用的兜底规则。
- 预期结果：条件测试和引擎解析遵循同一套生效规则；完整说明/覆盖分钟区间。如果引擎允许兜底，应展示兜底依据。10–19 分钟应该舍去、取半还是其他值，需要业务确认，本记录不擅自给出业务结果。
- 影响：页面规则测试无法解释引擎结果，可能导致课时边界计算与配置理解不一致。
- 证据：[10 分钟测试截图](screenshots/minute-10-unmatched.jpg)、[19 分钟测试截图](screenshots/minute-19-unmatched.jpg)、[引擎试算截图](screenshots/engine-10-minutes.jpg)；原文：[10 分钟](minute-10-observation.txt)、[19 分钟](minute-19-observation.txt)、[引擎结果](engine-10-minutes-observation.txt)。

## BUG-04：无效时间输入仍显示成功

- 页面：`/hss-config/rule → 测试计算引擎`。
- 前置参数：版本 2024-2025，Course Code=`PSY101`，Term Code=`2410`，Units=3，LEC，每周，权重=1，其他默认。
- 复现步骤：Days\&Time 先填 `Mon:11:00-10:00` 并试算，再填 `abc` 并试算。
- 实际结果：两种输入都返回原始课时 0、最终工作量 0、逻辑检查 PASS、计算状态“成功”。没有时间格式错误、结束早于开始等提示。
- 预期结果：普通课程的非法格式和逆序时间应阻止试算或明确标为解析失败/异常，指出具体输入问题。如果产品支持跨午夜，必须有明确格式和对应规则；本次同日逆序输入也不能静默当作 0 课时成功。
- 影响：错误输入被成功状态掩盖，用户可能把无效数据误认为有效的零工作量。
- 证据：[逆序时间截图](screenshots/engine-reversed-time.jpg)、[无效文本截图](screenshots/engine-invalid-time.jpg)；原文：[逆序时间](engine-reversed-time-observation.txt)、[无效文本](engine-invalid-time-observation.txt)。
- 范围限制：仅验证临时试算，没有执行正式结算或保存结果。

## BUG-06：历史消息详情按钮无可见反馈

- 页面：`/user/notify-message`。
- 复现步骤：分别点击以下记录右侧的“详情”：
  1. 2023-01-28 23:50，系统消息，“你好，欢迎 123 加入大家庭！”。
  2. 2023-01-28 23:45，通知公告，“我是 2，我开始 3 了”。
- 实际结果：点击后仍停留在原列表，没有出现详情弹窗、详情区域、跳转、新标签页或不可用提示。页面仍为 `/user/notify-message`，浏览器标签页数量没有变化。
- 预期结果：可用消息显示详情；历史业务已不存在时给出清晰提示，或禁用/隐藏不适用的详情按钮。
- 影响：用户无法判断按钮是否有效、消息是否缺失。
- 证据：[点击后的页面截图](screenshots/message-detail-no-response.jpg)。截图证明落点状态；操作过程及所点记录以本节步骤为准。

## 待确认疑点（不计入 6 项已复现缺陷）

### OBS-01：首页待办与任务中心口径不一致

- 首页显示待处理项 3，并列出三条待审开课计划：Development & Governance / 2025-2026 TERM_2，Applied Psychology / 2024-2025 TERM_1，Applied Psychology / 2025-2026 TERM_1。
- 点击“查看更多待办”，任务中心“全部待办”和四个审批节点均显示 0，列表为空；点击“刷新”后仍为空。
- 待确认：首页是否统计全系统待审计划，而任务中心只统计当前账号可审批任务。如果是不同口径，应明确文案；如果要求相同口径，则是数据/权限过滤缺陷。
- 证据：[首页统计](screenshots/home-summary.jpg)、[首页待办条目](screenshots/home-pending-records.jpg)、[任务中心](screenshots/task-empty.jpg)。

- 学期管理中，上述学年的 Term 1 / Term 2 / Summer 仍显示“编辑”和“设为当前”。
- 待确认：归档限制是否应该作用于其下学期，以及当前学期与当前启用学年的联动约束。
- 本次没有点击这些按钮，因此未验证后台是否阻止变更。
